## Overview

This guide explains how to build, run, and test the Housing Price Prediction API using Docker and Docker Compose.

### Architecture

```
┌─────────────────────────────────────────┐
│     Docker Compose                       │
│  ┌───────────────────────────────────┐  │
│  │  API Container (port 8080)        │  │
│  │  - FastAPI application            │  │
│  │  - Model loaded from /app/models  │  │
│  │  - Health checks enabled          │  │
│  └───────────────────────────────────┘  │
│                                          │
│  Volumes:                                │
│  - ./api/app → /app/app (code)          │
│  - ./models → /app/models (model files) │
└─────────────────────────────────────────┘
```

## Prerequisites

### 1. Docker Installation

Ensure Docker Desktop is installed and running:

```bash
# Check Docker status
docker info

# If not running, start Docker Desktop application
```

**Download:** https://www.docker.com/products/docker-desktop/

### 2. Trained Model

Ensure a trained model exists at:
```
./models/trained/housing_price_model.pkl
```

This model is automatically generated by step `07_registration` of the pipeline.

### 3. Environment Variables

Create/update `.env` file with required variables:

```bash
# W&B for prediction logging
WANDB_API_KEY=your-wandb-api-key-here
WANDB_PROJECT=housing-mlops-api

# Optional: GCS credentials (if using GCS model loading)
GCS_BUCKET_NAME=your-bucket-name
GCP_PROJECT_ID=your-project-id

# Optional: MLflow (if using MLflow model registry)
MLFLOW_MODEL_NAME=housing_price_model
MLFLOW_MODEL_STAGE=Production
MLFLOW_TRACKING_URI=http://localhost:5000
```

## Quick Start

### Option 1: Automated Test Script (Recommended)

Run the complete test suite:

```bash
./test_docker_api.sh
```

This script will:
1. ✅ Check if Docker is running
2. ✅ Build the Docker image
3. ✅ Start the API container
4. ✅ Wait for the API to be ready
5. ✅ Test all endpoints (health, root, model info, predictions)
6. ✅ Display results and logs

### Option 2: Manual Steps

#### Step 1: Build the Docker Image

```bash
# Build from scratch (no cache)
docker compose build --no-cache

# Or build with cache (faster for incremental changes)
docker compose build
```

#### Step 2: Start the API

```bash
# Start in detached mode (background)
docker compose up -d

# Or start with logs visible (foreground)
docker compose up
```

#### Step 3: Verify API is Running

```bash
# Check container status
docker compose ps

# Check health endpoint
curl http://localhost:8080/health

# View logs
docker compose logs -f api
```

## Container Management

### View Logs

```bash
# Follow logs in real-time
docker compose logs -f api

# View last 50 lines
docker compose logs --tail=50 api

# View logs from specific time
docker compose logs --since 10m api
```

### Restart Container

```bash
# Restart the API container
docker compose restart api
```

### Stop Containers

```bash
# Stop all containers (keeps data)
docker compose stop

# Stop and remove containers
docker compose down

# Stop and remove containers + volumes
docker compose down -v
```

### Rebuild After Code Changes

```bash
# Quick rebuild (uses cache)
docker compose up -d --build

# Full rebuild (no cache)
docker compose build --no-cache
docker compose up -d
```

## Troubleshooting

### Issue: Docker is not running

**Error:**
```
Cannot connect to the Docker daemon at unix:///Users/.../.docker/run/docker.sock
```

**Solution:**
```bash
# Start Docker Desktop application
# Wait for Docker to fully start
# Verify with: docker info
```

### Issue: Port 8080 already in use

**Error:**
```
Error starting userland proxy: listen tcp4 0.0.0.0:8080: bind: address already in use
```

**Solution:**
```bash
# Find what's using port 8080
lsof -i :8080

# Kill the process or change port in docker-compose.yaml
# Change: - "8081:8080" (host:container)
```

### Issue: Model not found

**Error:**
```
Model file not found: /app/models/trained/housing_price_model.pkl
```

**Solution:**
```bash
# Verify model exists locally
ls -lh ./models/trained/housing_price_model.pkl

# If missing, run the training pipeline step 07_registration
python main.py

# Or copy from registration output
cp src/model/07_registration/models/trained/housing_price_model.pkl models/trained/
```

### Issue: Container starts but health check fails

**Check logs:**
```bash
docker compose logs api
```

**Common causes:**
- Model file is corrupted or incompatible
- Python dependencies missing (rebuild image)
- Environment variables not loaded correctly

**Solution:**
```bash
# Rebuild container from scratch
docker compose down
docker compose build --no-cache
docker compose up -d

# Check health again
curl http://localhost:8080/health
```

### Issue: API responds with 500 errors

**Check container logs:**
```bash
docker compose logs --tail=100 api
```

**Common causes:**
- Model preprocessing pipeline mismatch
- Invalid input data format
- Missing environment variables

**Debug:**
```bash
# Enter container for debugging
docker compose exec api /bin/bash

# Inside container:
ls -la /app/models/trained/
python3 -c "import pickle; model = pickle.load(open('/app/models/trained/housing_price_model.pkl', 'rb')); print(model)"
```

## Performance Optimization

### Resource Limits

Adjust CPU and memory limits in `docker-compose.yaml`:

```yaml
services:
  api:
    deploy:
      resources:
        limits:
          cpus: '2'      # Maximum 2 CPU cores
          memory: 2G     # Maximum 2GB RAM
        reservations:
          cpus: '1'      # Guaranteed 1 CPU core
          memory: 1G     # Guaranteed 1GB RAM
```

### Volume Mounting

For production:
- Remove `:ro` from volumes if you need write access
- Use named volumes instead of bind mounts for better performance

### Caching

- First build takes ~2-5 minutes (downloads dependencies)
- Subsequent builds take ~30 seconds (uses cache)
- Use `--no-cache` only when needed (dependencies changed)
